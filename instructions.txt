ECHO — контекст проекта для продолжения разработки
1. Что за игра
ECHO — отдельная браузерная multiplayer-игра с исследованием мира и PvP.
Главная идея: игрок управляет своим существом/героем в большом изометрическом мире, исследует территорию, собирает еду, встречает других игроков и может вступать с ними в бой.
Игра экспериментальная и сейчас активно разрабатывается.
Репозиторий:
m1lker-go/echo-game
Главное правило: ECHO полностью отдельная игра. Cat Fighting не трогать.
ECHO сейчас живёт на том же VPS, но использует собственный сервер, клиент и отдельную БД.
2. Где всё находится
GitHub
Репозиторий:
m1lker-go/echo-game
Работаем непосредственно с ним.
Не создавать новые ветки без необходимости. Изменения делаем в main.
3. Сервер
ECHO работает отдельно от Cat Fighting.
- Node.js
- PM2
- процесс: echo-server
- порт: 5002
Cat Fighting использует другой сервер/порт, поэтому его нельзя случайно затронуть.
Примерно так:
Cat Fighting → 5001
ECHO         → 5002

4. Frontend
Клиент находится:
/var/www/echo-game/client/

Игра доступна через:
https://cat-fight.ru/echo/

Nginx настроен отдельно для ECHO:
/echo/              → ECHO client
/echo/api/          → Node.js :5002
/echo/socket.io/    → Socket.IO :5002

Это было важно, потому что раньше /echo/api/... иногда отдавал HTML игры вместо JSON из-за неправильной работы try_files + alias.
Сейчас это исправлено.
Проверялось:
https://cat-fight.ru/echo/
https://cat-fight.ru/echo/game.js
https://cat-fight.ru/echo/api/daily-activity?... 

API возвращает JSON.

7. Управление
Управление находится в:
client/player-controls.js

Логика специально сделана так, чтобы управление было визуально экранным, несмотря на изометрический мир.
То есть:
↑ = вверх экрана
↓ = вниз экрана
← = влево экрана
→ = вправо экрана

Диагонали работают через комбинации клавиш.
Есть также joystick.

9. Daily Activity
Мы уже сделали систему ежедневной активности.
Она учитывает:
- сколько времени игрок реально провёл в игре;
- сколько еды собрал;
- сколько PvP-побед сделал.
Основная таблица:
echo_daily_activity

Есть API:
/api/daily-activity

Для времени используется:
Europe/Moscow

через:
DAILY_TIME_ZONE

При этом часовой пояс можно переопределить через environment variable.
10. Важный момент с профилем
Сейчас полноценной авторизации ещё нет.
Для daily activity используется идентификатор профиля, который хранится на клиенте через:
localStorage

примерно:
echo.activityProfileId

То есть это не полноценная авторизация пользователя.
Это временная схема для привязки активности к профилю.
11. Socket.IO
Игра использует Socket.IO.
Сервер хранит игроков примерно через:
const players = new Map();

Также есть:
const activeFights = new Map();

Игроки регулярно отправляют координаты серверу.
Сервер рассылает состояние игроков через событие:
echo:players

Клиент получает список игроков и отображает их в мире.
12. PvP
PvP уже существует в базовом виде.
Есть:

В сервере сейчас используются, например:

Это пока базовая система, которую дальше будем развивать.
13. Важный текущий баг
Есть проблема, которую мы заметили во время разработки:
при каждом новом входе в игру создаётся ещё один персонаж/клон с 0 HP и 0 energy.
При этом это фактически собственный новый клон, а не настоящий второй игрок.
Его можно увидеть и вступить с ним в бой.
Это нужно будет отдельно расследовать.
Очень важно: не придумывать новую систему игроков, а разобраться, почему текущая система создаёт лишнюю запись/персонажа при подключении.

15. Последняя большая задача — границы мира
Сейчас мы как раз делали ограничение мира.
Было решено:
Игровое поле = 100 × 100 клеток
Размер одной клетки:
84 world units

Следовательно:
100 × 84 = 8400

Половина:
4200

Поэтому центр мира:
0, 0

а границы:
X = -4200 ... +4200
Y = -4200 ... +4200

16. Что уже сделали для границ
Клиент
Добавлен:
client/world-boundary.js

Он:
- рисует границу поля;
- затемняет всё за пределами игрового поля;
- рисует толстый светящийся синий контур;
- отслеживает положение локального игрока;
- блокирует рывок наружу.
Граница в изометрии получается ромбом — это нормально, потому что сам мир изометрический.
17. Ограничение движения
В:
client/player-controls.js

добавили:
const WORLD_HALF_SIZE = 4200;

и ограничение:
state.x = Math.max(
  -WORLD_HALF_SIZE,
  Math.min(WORLD_HALF_SIZE, state.x)
);

state.y = Math.max(
  -WORLD_HALF_SIZE,
  Math.min(WORLD_HALF_SIZE, state.y)
);

То есть клиент физически не должен увести игрока дальше поля.
