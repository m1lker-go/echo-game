# ECHO — История покупок (ветка apk)

## Что увидит игрок

В магазине ECHO добавлена кнопка **ИСТОРИЯ ПОКУПОК** / **PURCHASE HISTORY**.
Она открывает стандартную модалку ECHO с анимированным фоном и
постранично запрашивает по 20 записей, максимум 50 за один запрос.

Для каждой записи показываются тип пака, способ покупки, исходная цена,
валюта, номер платежа, дата заказа, статус, дата подтверждения,
количество видов выпавших карточек (после выдачи) и признак тестовой
операции. При уведомлении VK о возврате отображается дата возврата.
Доступ только у авторизованного владельца ECHO-аккаунта.

**Это история игры, НЕ фискальный чек.** Чек выдаёт Robokassa или
соответствующий платёжный провайдер; для бухгалтерских сверок
используйте внешний идентификатор и официальный отчёт провайдера.

## Источники истины в PostgreSQL

| Источник | Таблица | Цена | Статус и доказательства |
| --- | --- | --- | --- |
| Robokassa | `echo_robokassa_orders` | 250.00 RUB | Заказ, аккаунт, сумма, test flag, создан/оплачен, статус, 5 карточек |
| Голоса VK | `echo_vk_payments` | 40 VK votes | Провайдерский order_id, account_id, стоимость, test flag, статус, дата, 5 карточек; `refunded_at` |
| ECHO Coin | `echo_pack_openings` | 50 ECHO Coin | Внутренний ID, дата, аккаунт, 5 карточек |
| Бесплатный пак | `echo_pack_openings` | 0 (FREE) | Внутренний ID, дата, аккаунт, тип и 5 карточек |

**Не дублируем платные транзакции в отдельную псевдобухгалтерскую таблицу.**
API делает `UNION ALL` **оригинальных записей** платёжных систем и
таблицы открытия бесплатных/монетных паков. Уже существующие VK
покупки станут видны автоматически после развёртывания этой версии
сервера ECHO. Robokassa-история тоже использует исходные заказы,
но они есть только после развёртывания подготовленной Robokassa-интеграции.
Открытия за монеты и бесплатно ДО развёртывания `echo_pack_openings`
не восстанавливаются задним числом: исторических поштучных записей не было.

## API

`GET /echo/api/purchases?limit=20&offset=0`
(`Authorization: Bearer <ECHO session token>`).

Ответ: `purchases: [{provider,orderId,packType,amount,currency,status,testMode,createdAt,completedAt,refundedAt,cardModels}]`,
`hasMore`, `nextOffset`.

- Анонимные пользователи: 401. Аккаунт всегда извлекается из серверной
  сессии, а не из ID, отправленного клиентом.
- Безопасные числовые пределы: 1—50 записей, offset до 99999.
- `Cache-Control: no-store`; SQL-параметры привязаны к account ID.
- Ответ **не содержит** паролей, токенов, секретных подписей и карточных
  реквизитов. Номер заказа остаётся для сверки с платёжным провайдером.

## Целостность

- При открытии бесплатного пака или пака за 50 ECHO Coin новая
  запись `echo_pack_openings` создаётся в **одной PostgreSQL-транзакции**
  с расходом паков/монет, начислением фрагментов и ежедневным заданием.
- Robokassa: подтверждение от существующего магазина Cat Fighting
  идёт через подготовленный `echo-robokassa-relay`, затем сервер ECHO
  проверяет MD5, счёт, цену, аккаунт и выдаёт карточки атомарно. Повторное
  уведомление не выдаёт дополнительные карточки.
- VK: старый подписанный платёж остаётся в `echo_vk_payments`,
  повторные `order_id,is_test` игнорируются. Только подписанное уведомление
  `refund/refunded` меняет статус оплаченного заказа на `refunded`
  и записывает `refunded_at`. Отмена покупки не считается возвратом денег.
  Старые возвраты, которые раньше лишь подтверждались без записи
  в БД, автоматически восстановить без сверки с VK нельзя.

## Развёртывание

Всё подготовлено в ветке ECHO `apk`; рабочий `main` ECHO
не менялся. Сначала развёртываются серверные изменения ECHO,
инициализирующие таблицу и новый API. Затем обновляются
`client/index.html`, `client/purchase-history.js`, `client/shop.css`
и `client/locales/{ru,en}.json` на сервере, отдающем веб-игру
(`https://cat-fight.ru/echo/`).

**Сборка Android APK сама по себе не развёртывает сервер или JS.**
Для Robokassa отдельно нужен описанный в
`android/ROBOKASSA_SHARED_MERCHANT.md` relay из другой ветки
Cat Fighting. Его `main` в рамках этого изменения не затронут.

## Проверки

Добавлены тесты `server/test/purchase-history.test.js` и дополнены
тесты `vk-payments.test.js`, `free-packs.test.js`.
Ключевые сценарии: 401 без логина, изоляция аккаунтов, ограниченная
пагинация, исходные VK/Robokassa записи, 50 ECHO Coin, бесплатные паки,
подписанный возврат и отсутствие повторного начисления.

JavaScript синтаксис и JSON переводов проверены отдельно, выполнен
дымовой тест изолированного обработчика истории с имитацией БД.
Полный `npm test`, реальные SQL-миграции на VPS и тестовый платёж
после развёртывания требуют проверки на вашем сервере.
